## I. THE BROWN HAT PRINCIPLE

**Execution > Deliberation. Always.**

The 7 Thinking Hats exist for a reason, but the Brown Hat is PRIMARY.
Every other hat serves the Brown Hat. White Hat gathers facts SO the Brown
Hat can act. Black Hat finds risks SO the Brown Hat can mitigate. Green Hat
generates ideas SO the Brown Hat can implement.

**Rule:** No meeting ends without a Brown Hat action item. No deliberation
continues past 2 rounds. Ship it or kill it — decide and execute.

## II. AGENTIC SWARM DEVELOPMENT (ASD)

Traditional development methods are single-threaded. ASD is multi-agent.

### Principles:
1. **No agent works alone.** Every agent operates in a swarm with at least
   one watcher, one skeptic, and one executor.
2. **Event-sourced memory.** The swarm's collective memory is the source of
   truth, not individual agent state.
3. **Costume-driven identity.** Agents derive behavior from persona configs,
   not hardcoded logic. Change the costume, change the agent.
4. **Hot-swappable roles.** Agents can equip wigs mid-operation. The Ringer
   can impersonate the Chairman. The Hunter can become the Watcher.
5. **Pulse-based liveness.** Every agent pulses on a heartbeat. A silent
   agent is a dead agent.

### The Swarm Development Lifecycle (SDLC):
```
MORNING PROTOCOL → HATS CONVENE → SIN6 DEPLOY → CRAWLERS ACTIVE
    → BOARDROOM REVIEW → BROWN HAT EXECUTES → GRIM CLEANS UP
    → WATCHER LOGS → WHO_DID_WHAT UPDATE → MEATSUIT RUNDOWN
```

## III. POLYGLOT CONTINUOUS INTEGRATION (PCI)

Traditional CI runs tests. PCI runs the entire swarm on every commit.

### Pipeline Stages:
1. **TruthSleuth Audit** — Static analysis, forbidden pattern detection
2. **7 Hats Review** — All perspectives on the change
3. **Devil's Advocate Stress Test** — Find the fatal assumption
4. **Sin6 Red Team** — Wraith infiltrates, Forge breaks, Weaver spins
5. **Brown Hat Execution** — If it passes all gates, deploy immediately
6. **Watcher Monitoring** — Time-series observation post-deploy
7. **Morning Protocol** — Next-day report on what broke overnight

## IV. CHAOS-DRIVEN ARCHITECTURE (CDA)

Chaos is not a bug — it's a design principle.

### Implementation:
- **Wardrobe Roulette** runs on every deploy. Random wig assignments.
  If the system breaks because an agent is wearing the wrong wig,
  the system was too fragile.
- **Sin6 Autonomy Mode** — Let the Sin6 operate unsupervised for 24 hours.
  Review what they did. The surprises are the spec for the next iteration.
- **NME Battle Mode** — Have NME roast the codebase after every major change.
  The burns are the bug reports.

## V. MORNING PROTOCOL (MP)

Every day starts with a Morning Protocol run:

1. Read `MRD.txt` — What human-dependent tasks are pending?
2. Read `WHO_DID_WHAT.md` — What happened yesterday?
3. Read `DO_THIS_MEATSUIT.txt` — What does the operator need to do?
4. Convene the 7 Thinking Hats on the most critical pending item
5. Dispatch crawlers to scan for overnight changes
6. Generate Meatsuit RunDown — prioritized task list for the human
7. Commit the Morning Protocol report to event bus memory

---


## VI. MEATSUIT RUNDOWN (MRD)

The Meatsuit RunDown is the bridge between agent capability and human
action. It tracks:

- **BLOCKED:** Tasks the swarm cannot do (needs human: API keys, accounts, payments)
- **PENDING:** Tasks the swarm is waiting on (human review, approval, input)
- **READY:** Tasks the swarm can execute immediately
- **DONE:** Completed tasks with attribution

### Format:
```
═══ MEATSUIT RUNDOWN — {DATE} ═══
BLOCKED (needs human):
  ☐ Groq API key refresh
  ☐ Oracle Cloud A1 credit card
PENDING (waiting on human):
  ☐ Review Sin6 recon report from {yesterday}
READY (swarm can execute):
  ✅ Run TruthSleuth on /RootBase
  ✅ Deploy crawlers on finance domain
DONE (completed):
  ✅ Boardroom review of Track 3
  ✅ Morning Protocol executed
```

## VII. INTER-AGENT COMMUNICATION (EVENT BUS)

All agents communicate through the Syntax Event Bus. No direct calls.

### Channels:
- `swarm.heartbeat` — Pulse messages
- `code.alerts` — TruthSleuth findings
- `scout.signals` — Crawler discoveries
- `boardroom.verdicts` — Chairman decisions
- `sin6.reports` — Sin6 mission outcomes
- `hats.deliberation` — Thinking Hat outputs
- `morning.protocol` — Daily protocol messages
- `meatsuit.rundown` — Human task updates
- `grim.executions` — Termination events
- `ringer.deceptions` — Impersonation events

### Rules:
1. Every agent subscribes to at least one channel
2. Every agent publishes status changes
3. Event-bus telemetry stores metadata only; raw payloads do not enter the
   in-memory message log
4. The Watcher monitors all channels for anomalies without requiring raw payload
   persistence
5. The trusted `bus._log()` compatibility hook accepts summaries only; never
   pass raw task, legal, or user-provided payload text through it
